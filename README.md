# wutis_quantum_to_quantum

WUTIS semester project for WS 25/26.

The repository combines:

- classical market-data ingestion and feature engineering
- quantum neural network (QNN) training with Qiskit + PyTorch
- portfolio optimization and backtesting on predicted returns and covariances

The current codebase is organized as a script-driven pipeline rather than a Python package. Most scripts are intended to be run from the repository root.

## Project Goal

The project explores Markowitz-style portfolio optimization with forecasts generated by quantum neural networks:

- expected returns are predicted from engineered market features
- covariance matrices are predicted from historical return structure
- predicted returns and covariances are fed into a long-only optimizer
- the resulting weights are evaluated in a weekly rebalancing backtest

## End-to-End Workflow

1. Define the asset universe in `source/assets.csv`.
2. Fetch daily historical market data from Alpaca with `data/fetch.py`.
3. Add indicators and merge all assets into one panel with `data/preprocess.py`.
4. Build model-ready datasets with either:
   - `data/datasets.py` for one-step-ahead daily targets
   - `data/datasets_weekly.py` for weekly targets aligned with the backtest flow
5. Train QNN models with `qnn/train.py` or tune them with `qnn/tuning.py`.
6. Visualize predictions and covariance structure with scripts in `analysis/`.
7. Run `Optimizer/backtest.py` to generate portfolio weights, KPIs, and performance plots.

## Requirements

- Python `3.11.14` was used for the project
- Alpaca API credentials are required for data fetching
- commands should be run from the repository root so that relative imports and config paths resolve correctly

Install the base environment with:

```bash
bash install.sh
```

`install.sh` does the following:

- upgrades `pip`, `setuptools`, and `wheel`
- installs packages from `requirements.txt`
- verifies that Qiskit, PyTorch, and `TorchConnector` are available

### Additional Dependency Note

`Optimizer/optimizer.py` imports `cvxpy`, but `requirements.txt` does not currently list it. If you want to run the optimizer/backtest pipeline, install it manually in the same environment.

## Configuration

### `config/config.yaml`

This file is required by `data/fetch.py` and is not created automatically.

```yaml
alpaca_api:
  secret_key: "your_secret_key"
  api_key: "your_api_key"
  base_url: "https://paper-api.alpaca.markets"
```

Actual path expected by the code: `config/config.yaml`

### `config/data_config.yaml`

Controls the data universe, feature engineering, split settings, and output paths.

Important fields currently used by the scripts:

| Key | Meaning |
| --- | --- |
| `assets` | Initial asset list. This can be overwritten by preprocessing based on successfully merged symbols. |
| `start_year` | First year used for Alpaca history requests. |
| `records_number_threshold` | Minimum number of rows required to keep a fetched ticker. |
| `indicators` | Indicator definitions applied in `data/preprocess.py`. |
| `train_size` | Time-based train/test split ratio. |
| `lookback_window` | Used by `data/datasets.py`; interpreted as weeks by `data/datasets_weekly.py`. |
| `cov_window` | Used by `data/datasets.py`; interpreted as weeks by `data/datasets_weekly.py`. |
| `use_past_cov_in_features` | Adds historical covariance information to covariance-model features. |
| `use_past_ret_in_features` | Adds historical returns to returns-model features. |
| `paths.raw` | Raw market data output directory. |
| `paths.processed` | Processed dataset output directory. |
| `paths.scalers` | Saved `StandardScaler` objects. |
| `paths.plots` | Analysis plots directory. |

Scripts also mutate this file:

- `data/fetch.py` updates `n_assets` to the count of successfully fetched assets
- `data/preprocess.py` updates `assets` to the symbols that survived merging

### `config/model_config.yaml`

Defines output folders for the QNN stage:

- `paths.results`: prediction `.npz` files and saved PyTorch model weights
- `paths.plots`: circuit diagrams and learning-curve plots
- `paths.models`: present in config, but the current training script saves `.pth` files into `paths.results`

## Running The Pipeline

### Option 1: Run the bundled data pipeline

```bash
python data/data_pipeline.py
```

This script:

- deletes `data/raw/`
- deletes `data/processed/`
- runs `data/fetch.py`
- runs `data/preprocess.py`
- runs `data/datasets.py`

Use this only if you want to rebuild the daily dataset flow from scratch.

### Option 2: Run each step manually

Fetch daily bars from Alpaca:

```bash
python data/fetch.py
```

Expected outputs:

- `data/raw/tickers/*.csv`
- updated `n_assets` inside `config/data_config.yaml`

Add indicators and merge all tickers:

```bash
python data/preprocess.py
```

Expected outputs:

- `data/raw/merged_data.csv`
- updated `assets` inside `config/data_config.yaml`

Create the default daily datasets:

```bash
python data/datasets.py
```

Expected outputs:

- `data/processed/qnn_datasets.npz`
- `data/processed/scalers/qnn_cov_scaler.joblib`
- `data/processed/scalers/qnn_ret_scaler.joblib`

Create the weekly datasets used by the backtesting logic:

```bash
python data/datasets_weekly.py
```

This script writes the same output filename, `data/processed/qnn_datasets.npz`, but with weekly targets:

- next-week aggregated log returns
- next-week realized covariance built from daily returns within the following week

If you plan to evaluate the optimizer/backtest flow, this weekly dataset builder is the relevant one.

## QNN Training And Tuning

Train both returns and covariance models using the hard-coded settings in `qnn/train.py`:

```bash
python qnn/train.py
```

Current default training runs in `qnn/train.py`:

- returns model: `mode="returns"`, `n_qubits=6`, `n_layers=6`, `feature_mode="angles"`, `circuit_type="rxrz"`
- covariance model: `mode="cov"`, `n_qubits=7`, `n_layers=6`, `feature_mode="pca"`, `circuit_type="rxrz"`

Generated artifacts are written under:

- `qnn/results/` for prediction files and saved `.pth` weights
- `qnn/plots/` for circuit diagrams and learning curves

Run Optuna tuning:

```bash
python qnn/tuning.py
```

The current script runs a demo study for returns with:

- `10` trials
- `10` epochs per trial
- SQLite storage at `qnn_optuna.db`

Important note: `analysis/test_plot.py` currently looks for `qnn/results/qnn_torch_returns_angles_hybrid_predictions.npz`. If your training run produced a differently named prediction file, update the script or rename/copy the artifact before running it.

## Optimizer And Backtesting

Run:

```bash
python Optimizer/backtest.py
```

What it does:

- loads merged daily log returns from `data/raw/merged_data.csv`
- loads predicted weekly returns from `Optimizer/prediction data/qnn_returns_angles_hybrid_rxrz_predictions.npz`
- loads predicted covariance vectors from `Optimizer/prediction data/qnn_cov_pca_hybrid_rxrz_predictions.npz`
- rebuilds symmetric covariance matrices and projects them to positive semidefinite form
- computes long-only portfolio weights with `cvxpy`
- compares the QNN portfolio against an equal-weight benchmark

Generated outputs:

- `Optimizer/backtest results/cumulative_performance_comparison.png`
- `Optimizer/backtest results/top_asset_weights.png`

### Important Path Assumption

The training script saves prediction artifacts to `qnn/results/`, while the backtest script reads them from `Optimizer/prediction data/` with hard-coded filenames.

Before backtesting, you currently need to either:

- copy the desired prediction `.npz` files into `Optimizer/prediction data/`, or
- edit `Optimizer/backtest.py` to point at the files produced by your training run

The repository currently contains generated outputs in addition to source code, including:

- `data/raw/merged_data.csv`
- `data/processed/qnn_datasets.npz`
- plots under `analysis/plots/`
- predictions under `Optimizer/prediction data/`
- backtest figures under `Optimizer/backtest results/`
- QNN figures under `qnn/plots/`

This means the repository is usable both as:

- a reproducible pipeline you can rerun from raw market data, and
- a snapshot containing intermediate and final artifacts from earlier runs

## Current Caveats

- There is no automated test suite in the repository at the moment.
- Several scripts rely on hard-coded filenames rather than a single artifact registry.
- `data/data_pipeline.py` rebuilds the daily dataset flow, not the weekly dataset flow.
- `qnn/train.py` stores model weights in `qnn/results/` even though `config/model_config.yaml` also defines `qnn/models/`.
- `Optimizer/backtest.py` assumes prediction files already exist in `Optimizer/prediction data/`.
